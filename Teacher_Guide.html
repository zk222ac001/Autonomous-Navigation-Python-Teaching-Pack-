TEACHER EDITION • PYTHON • BEGINNER ROBOTICS

Teach a robot to find
and follow a route

Three 90-minute lessons, four runnable demonstrations, a student lab and a homework project.

Teaching approach: start with a small delivery robot moving across a classroom. Students first represent the room, then plan a route, then simulate movement. Use the same map throughout so each new idea builds on something familiar.

Prerequisites: variables, comparisons, loops, functions, lists and basic tuples. Explain dictionaries before A*. No robotics experience is assumed. The examples use the Python standard library; the optional animation uses Tkinter.

Your first preparation step: extract the pack, open a terminal in its folder, run python 01_grid_basics.py, then python 02_astar_demo.py. Open the simulation with python 03_robot_simulation.py. Practice changing one free cell to an obstacle in navigation.py. You now have the first classroom demonstration.

What students should be able to do

  • Explain the roles of a map, localization, planning and control.
  • Represent free space and obstacles using a two-dimensional Python list.
  • Calculate and explain A*'s g, h and f scores.
  • Read, modify and test a working A* implementation.
  • Convert grid cells to waypoints and simulate following them.
  • Explain the gap between an ideal simulation and a real robot.

Lesson 1 — Intro to autonomous navigation

1. Begin with a question, not an algorithm

Say: “Imagine a robot delivering a book from the classroom door to my desk. There are tables in the way. What does the robot need to know?” Give students two minutes in pairs before collecting answers.

QuestionNavigation componentOur classroom assumption
What is around me?Perception and mappingWe supply the obstacle map.
Where am I?LocalizationWe know the simulated position exactly.
Where should I go?Path planningA* finds grid cells from start to goal.
How do I move there?ControlA simulated robot turns, then drives toward each waypoint.

Autonomous navigation means making movement decisions toward a goal using available information. A* is a search algorithm; it is not a trained neural network. It does not need a dataset or an AI API.

Ask: “If a chair moves after planning, does the old route automatically change?” Expected answer: no. A system must detect the change, update its map and replan. Our supplied demo uses a static map.

2. Grid maps and pathfinding basics

Divide a room into cells. In this simplified map, 0 means free and 1 means blocked. Each move goes up, down, left or right and costs one unit. Diagonal moves are not allowed.

grid = [
    [0, 0, 0],
    [0, 1, 0],
    [0, 0, 0],
]
position = (0, 0)       # (row, column)
print(grid[1][1])      # 1: the central cell is blocked

3. Live coding: valid neighbors

row, col = (0, 0)
for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
    nr, nc = row + dr, col + dc
    if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]):
        if grid[nr][nc] == 0:
            print((nr, nc))

Ask students to predict the output before running. Explain bounds before access: Python permits negative indexing, so forgetting bounds can accidentally connect opposite edges of the map.

Exercise: complete student_neighbors in student_tasks.py. Trace the four directions on paper first. Test a corner, an edge and a cell next to obstacles.

Exit questions: What does grid[2][1] mean? Why must an obstacle not be a neighbor? Which component tells the robot where it is?

Lesson 2 — A* algorithm theory

4. Explain the three scores

Say: “For each candidate cell, we combine how far we have already travelled with an optimistic estimate of how far remains.”

ScoreMeaningExample
g(n)Best known cost from start to candidate n.Three moves so far gives g = 3.
h(n)Estimated cost from n to the goal.Two rows and four columns away gives h = 6.
f(n) = g(n) + h(n)Priority used to select the next candidate.3 + 6 = 9.

The estimate used here is Manhattan distance: abs(row - goal_row) + abs(col - goal_col). It ignores obstacles. For four-direction moves of cost one, obstacles may force a longer route but cannot make it shorter than this estimate.

A heuristic is admissible if it never overestimates the true minimum remaining cost. It is consistent if h(n) ≤ cost(n,m) + h(m) for each edge, with zero at the goal. Manhattan distance satisfies both for this grid model. These properties justify shortest-path results; an arbitrary estimate does not.

Changing the movement rules changes the heuristic. If diagonal steps also cost one, Manhattan distance can overestimate: (0,0) to (1,1) takes one diagonal step but Manhattan gives two. Keep the first lab strictly four-directional.

5. A worked hand trace

Use the 3 × 3 map above: start (0,0), goal (2,2), centre blocked. Our code generates neighbors in the order up, down, left, right and breaks equal f scores by insertion order. All the following candidates have f = 4; equal scores are common.

Returned route: (0,0), (1,0), (2,0), (2,1), (2,2). Ask why the right-hand route is also optimal. Do not claim A* always explores only its final path.

6. Search pseudocode

Give the start g = 0 and add it to the frontier.
While the frontier is not empty:
    Remove a candidate with the smallest f.
    Skip it if this is an outdated queue entry.
    If it is the goal: reconstruct and return its route.
    For each legal neighbor:
        new_cost = current cost + 1
        If this improves the neighbor's best known cost:
            Record its cost and parent.
            Add a new entry with f = new_cost + heuristic.
Return “no route”.

Key distinction: stop when the goal is removed as the best candidate, rather than merely when it is first encountered. Track parents so that the result is an ordered route, not a collection of visited cells.

7. Implementing A* in Python

Open navigation.py and explain it in five chunks:

  1. neighbors and manhattan describe the problem.
  2. frontier holds candidates. heapq.heappop selects the smallest priority; the list itself is not a fully sorted list.
  3. g_score stores the cheapest route found so far. came_from maps each cell to its predecessor.
  4. The loop updates a neighbor only when the new route is cheaper. An updated candidate gets a new queue entry; stale entries are skipped later.
  5. At the goal, follow parent pointers backward, then reverse the list.

A heap item is (f_score, sequence_number, g_score, cell). The sequence number gives stable insertion-order tie-breaking. The saved g value lets the implementation detect outdated entries. Students need not implement a heap themselves.

tentative_g = popped_g + 1
if tentative_g < g_score.get(neighbor, float('inf')):
    came_from[neighbor] = current
    g_score[neighbor] = tentative_g
    f_score = tentative_g + manhattan(neighbor, goal)

Explain float('inf') as “no known finite cost yet.” A tuple can be a dictionary key; a list cannot. The supplied functions use tuples consistently.

8. Demonstrate, predict, change

Run 02_astar_demo.py. Ask students to predict what happens if GRID[0][1] becomes 1. Then block both neighbors of the start: GRID[0][1] = 1 and GRID[1][0] = 1. The start is valid but disconnected, so the program reports no route.

Finally run 04_compare_search.py. Using h = 0 turns this into uniform-cost search. With all edges costing one, it has breadth-first cost ordering. Compare path cost and expanded cells separately: fewer expansions do not mean a shorter route. A* may tie with uninformed search on some maps.

Exit questions: Calculate f when g = 4 and h = 3. Why does h ignore walls? Why do we store parents? What should the robot do when the frontier empties without finding the goal?

Lesson 3 — Robot control for path following

9. From cells to physical waypoints

A* returns cells such as (0,0), (0,1), (0,2). A controller needs target positions. Put each target at its cell centre. For N rows and cell width s metres:

x = (column + 0.5) * s
y = (N - row - 0.5) * s

Our map has five rows and s = 1 metre, so start (0,0) becomes (0.5,4.5) metres and goal (4,5) becomes (5.5,0.5) metres. World x increases right, world y increases up. Screen y increases downward, so the drawing reverses y again.

10. A simple feedback controller

The robot state is (x, y, theta). The angle theta is in radians, measured counterclockwise from the positive x direction. Each update compares the current state to the next waypoint.

dx = target_x - x
dy = target_y - y
desired_heading = atan2(dy, dx)
heading_error = wrap_angle(desired_heading - theta)
angular_speed = clamp(KP * heading_error, -MAX_TURN, MAX_TURN)

atan2 uses both coordinate differences and handles all four quadrants. Wrapping the heading error into [−π, π) makes the robot turn through the shorter angular difference. Proportional control gives a larger turn command for a larger error, within the speed limit.

Our ideal controller turns in place until aligned, then moves straight toward the waypoint. It limits the movement to the remaining distance so it cannot step past the target. When it arrives, it selects the next waypoint. After the final waypoint, it stops updating motion.

x_next = x + v * cos(theta) * dt
y_next = y + v * sin(theta) * dt
theta_next = theta + omega * dt

These are the basic discrete kinematic updates. In controller.py, turning uses v = 0 and driving uses omega = 0. Parameters have units: v in m/s, omega in rad/s and dt in seconds. A 0.05-second update means 20 simulation steps per second; GUI scheduling is approximate wall-clock timing.

Discuss three different concepts: a waypoint defines where to go; a controller computes a command; a physical motor interface applies it. This pack models the first two and does not send motor commands.

11. Run the visual demonstration

Run 03_robot_simulation.py. Blue shows the planned route; pale green shows expanded free cells; dark cells are obstacles; orange is the robot. Start and pause the movement. Ask students to describe what happens at a corner. If a window cannot open, run with --headless.

Experiment: reduce MAX_SPEED in controller.py from 0.8 to 0.4 and rerun. The route remains the same; movement takes more simulated time. Change MAX_TURN to observe turns. Change one parameter at a time.

Simulation boundary: this is a point robot in a known, static world with perfect position. The drawn circle has no physical footprint. A real robot needs obstacle clearance for its body, localization, sensor updates, motor feedback and a reliable stop mechanism. Do not copy this simulator directly into a motor driver.

12. Optional bridge to differential-drive robots

For track width L and desired forward speed v and angular speed omega, ideal wheel linear speeds are v_left = v − omega × L/2 and v_right = v + omega × L/2. Wheel angular speed is linear speed divided by wheel radius. This is a conceptual extension; the supplied code has no hardware implementation.

Lab and homework briefing

Lab — a classroom delivery route

Work in pairs. One student predicts and explains; the other edits and runs. Swap roles halfway through.

  1. 5 minutes: complete the two functions in student_tasks.py and run its checks. If this was completed in lesson 1, explain your functions to your partner.
  2. 8 minutes: create a 6 × 8 map with at least eight blocked cells. Use start (0,0) and goal (5,7). Keep one route open. Update GRID, START and GOAL in navigation.py.
  3. 7 minutes: run the planner and simulator. Record the route cost and expansion count. Verify that every move changes exactly one coordinate by one and enters a free cell.
  4. 5 minutes: block both neighbors of the start. Record how the planner and simulator respond. Restore the reachable map.
  5. 5 minutes: explain g, h and f using one cell in your map, then explain why the controller must turn at a corner.

Submit: your changed map, route/cost output, one unreachable-case output and a short explanation of planning versus control. A screenshot of animation is optional; terminal output is sufficient.

The included default-map unit test expects cost 9. After changing the map, keep a copy of the original for that test or update its expected cost using an independently checked answer. Do not change an expected result solely to make a failing test pass.

Teacher answers and troubleshooting

Starter solutions

def student_manhattan(a, b):
    return abs(a[0] - b[0]) + abs(a[1] - b[1])
def student_neighbors(grid, cell):
    result = []
    row, col = cell
    for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
        nr, nc = row + dr, col + dc
        if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]):
            if grid[nr][nc] == 0:
                result.append((nr, nc))
    return result

The starter grid is assumed nonempty and rectangular; the completed A* implementation validates those properties before searching.

Expected answers

  • grid[2][1] is the third row, second column.
  • Default start neighbors: (1,0) and (0,1). Default start heuristic: 9.
  • At (2,2), valid neighbors are (3,2), (2,1), (2,3).
  • g = 4 and h = 3 gives f = 7. f is a priority estimate, not a guaranteed final route length.
  • Default shortest path costs 9; the 3 × 3 hand-trace path costs 4.
  • h ignores walls to give an inexpensive optimistic estimate.
  • Parent links recover an ordered path. Expansion order is not the path.
  • An exhausted frontier means there is no route under the supplied map and movement rules. Do not move the robot toward an unverified target.
  • Changing speed changes traversal time, not the A* route.
